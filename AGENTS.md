# AGENTS.md — правила работы Codex с «Последней веткой»

## Проект и безопасные границы
- «Последняя ветка»: постапокалиптическая Самара, художественная версия станции «Гагаринская», 2D Canvas/PWA для iPhone.
- `main` — стабильная PROD: https://kidgat.github.io/poslednyaya-vetka/
- `dev` — тестовая публикация: https://poslednyaya-vetka-dev.pages.dev/
- **Без прямого разрешения автора не отправлять коммиты в `main` или `dev`, не делать merge, release, tag, деплой и не менять настройки публикаций.**
- Для каждой задачи создавать отдельную ветку **от актуальной `dev`** и открывать PR **в `dev`** на проверку автора.
- Не удалять и не переписывать историю веток, включая `release/*` и `backup/*`.

## Источники истины
- Техническое описание и точные команды: `CLAUDE.md` (унаследованный файл правил проекта; это документация, **Claude Code не требуется**).
- Схема DEV/PROD: `docs/PROD_DEV.md`.
- Утверждённые решения: `docs/CANON_v1.46_TECH.md` и профильные документы в `docs/`. Не менять сюжет, канон или графику сверх согласованной задачи.
- Не путать реализованное и запланированное: проверить исходный код и статус документа перед работой.

## Как менять код
- Изменять исходники в `src/`. `index.html` — **результат сборки**, не редактировать вручную: `node tools/build.mjs`.
- Порядок модулей задаёт `MODULES` в `tools/build.mjs`; при новом модуле обновить этот список.
- Не читать целиком большой `index.html`, `src/24-s1-art.js` (data URI), `archive/` или объёмные отчёты без необходимости.
- Оберегать PWA/offline, обработку сенсорных событий, сохранения и изоляцию PROD/DEV (`pv.*` против `pv.dev.*`).
- Не менять версию, `CONFIG.VERSION`, `sw.js` CACHE или формат сохранений без отдельного задания автора.

## Проверка перед PR
1. `node tools/build.mjs`
2. `node tools/build.mjs --check`
3. `node tools/art/pack.mjs --check`
4. Запустить все доступные `tests/*.test.js` через Node.js; особо проверить `tests/compat.test.js` при работе с сохранениями.
5. Сверить `git diff`, приложить в PR: что изменено, как проверено, что проверить на iPhone.

## Первый запуск Codex
При первом обращении **ничего не менять в игровом коде**. Прочитать `AGENTS.md`, `CLAUDE.md`, `docs/PROD_DEV.md`, структуру `src/` и `tests/`; проверить состояние Git и перечислить команды сборки и тестирования. Сообщить автору краткий отчёт и ждать конкретного ТЗ.
