# Последняя ветка — прототип 0.5.2

Постапокалиптическая Самара, 2055. Станция «Гагаринская» — **художественная модель, не схема реальной станции**.
Сборка 0.5.2 (основа — 0.5, точечные правки 0.5.1 и 0.5.2): станция в разрезе с тремя уровнями — улица у вестибюля, верхний ярус, платформа. Между платформой и ярусом — бетонный лестничный марш на наклонной плите с просветом под ним; огонь в бочке корректно уходит за героя. Жители и охрана анимированы, по улице бродят мутанты. Боёв, экономики и строительства нет.

## Структура проекта

```
poslednyaya-vetka/
├── index.html        ← текущая сборка (вся игра в одном файле, без зависимостей)
├── manifest.webmanifest, sw.js, icon-*.png  ← офлайн-режим и иконка на экран «Домой»
├── README.md         ← запуск, управление, устройство кода, тест-план, ограничения
├── CHANGELOG.md      ← изменения по версиям + перечень изменённых разделов кода
└── archive/
    ├── poslednyaya_vetka_prototype_01.html   ← прототип 0.1 (ChatGPT)
    ├── v0.2.html … v0.5.1.html               ← прошлые сборки
    └── v0.2-to-v0.3.diff … v0.5.1-to-v0.5.2.diff ← полные diff между версиями
```

Правила команды: текущая сборка — всегда `index.html`; при выпуске новой версии предыдущая копируется в `archive/vX.Y.html`, в `CHANGELOG.md` добавляется раздел. Правки — точечные. Версия в коде — `CONFIG.VERSION`.

## Запуск

**Windows / Mac:** двойной клик по `index.html`. Внешних файлов нет.

**Через локальный сервер** (или чтобы открыть с iPhone в той же Wi-Fi-сети):
```
cd poslednyaya-vetka
python -m http.server 8000        # Windows: py -m http.server 8000
```
Затем `http://localhost:8000` или `http://<IP-компьютера>:8000` на iPhone.

**iPhone:** надёжнее всего по ссылке в Safari. Открытие `.html` из «Файлов» на iOS работает не везде одинаково. Полный экран: «Поделиться» → «На экран Домой».

## Офлайн на iPhone (с 0.5.1)

Игра умеет работать без интернета как приложение на экране «Домой». Для этого папку проекта нужно один раз выложить на любой https-хостинг (GitHub Pages, Netlify и т. п.), затем:
1. открыть ссылку в Safari при наличии интернета и подождать пару секунд — игра сохранится в кэш;
2. «Поделиться» → «На экран Домой»;
3. дальше запускать с иконки — сеть не нужна.

Файлы офлайн-режима: `manifest.webmanifest`, `sw.js`, `icon-180.png`, `icon-512.png`. При выпуске новой версии поменять `CACHE` в `sw.js` — тогда устройства скачают обновление при следующем выходе в сеть. Открытие с диска (`file://`) и опубликованный артефакт claude.ai работают как раньше, но без офлайн-кэша.

## Маршрут по станции

Платформа → **бетонный марш** в конце жилого сектора → лестничная клетка → мастерская, медпункт, энергоблок, **шлюз**, насосная → гермоворота шлюза → **улица у вестибюля**. Обратно тем же путём: «▼ Вход в метро» у дверей вестибюля, «▼ Спуститься» на верхней площадке марша.

Схема управления лестницей (окончательная): у нижней площадки — кнопка «▲ Подняться» (ПК: `W` / `↑`), у верхней — «▼ Спуститься» (`S` / `↓`). Одно нажатие — герой сам проходит весь марш обычным шагом; ◀ ▶ и повторные нажатия в это время игнорируются.

## Схема лестницы (мировые координаты)

| Элемент | Значение |
|---|---|
| Нижняя площадка | платформа, y 219; герой встаёт на x 652; кнопка ▲ при x 636–666 |
| Марш | x 666 → 846, 20 ступеней по 9 px (высота 6 px, последняя 7), подъём 121 px, ~34° |
| Проём в полу яруса и перекрытии | x 752–846, y 96–122 (с x 752 голова героя доходит до низа перекрытия) |
| Верхняя площадка | ярус, y 98; герой встаёт на x 862; кнопка ▼ при x 846–870; проём в стене в мастерскую x 856–874 |
| Верхний ярус проходим | x 852–1856 |

Почему нет пересечений: проём лежит целиком в бывшей комнате «ЗАВАЛ» (x 740–860) — теперь это «Лестница», обломки остались у её западной стены. Западнее проёма — недоступная столовая, поэтому над пустотой никто не ходит. Медпункт, шлюз и остальные комнаты не тронуты; стремянка и люк в медпункте убраны. Колонны x 660 и 820 стоят позади марша. Внизу сдвинуты синие бочки (x 598–624), лампа (x 708) и граница прогулки жителя (до x 630).

## Устройство кода (`index.html`)

- **CONFIG** — `FLOORS` (platform y 219, upper y 98, surface y −61, проходимые участки), `STAIRS`, `GATES` (пары точек перехода с подписями кнопок), камера, параллакс, цвета темноты внизу и снаружи.
- **WORLD** — `drawStairs` (марш и проём), `stairTopY` (высота ступени под x), `drawRail` (перила). Слои, рисуемые один раз: `sky` (0.15), `ruins` (0.5), `surface` (улица, вестибюль, грунт, наклонный ход), `back` (0.9), `main`, `fore` (1.22). Мир по вертикали — от y −280 (небо) до 270 (пути).
- **PLAYER_SPRITE** — палитры одежды (`HERO_PAL`, `GUARD_PAL`, `WORKER_PAL`…); `personSet()` собирает кадры: ходьба, дыхание, моргание, по запросу сидя (`drawSitFrame`) и лёжа (`makeLying`); `drawMutantFrame` — 6 кадров мутанта.
- **ACTORS** — жители, охрана, мутанты: `placeActors()` — кто где стоит; `updateActors()` — оглядывание, блуждание в своих границах, пауза. Без столкновений и диалогов.
- **INPUT / PLAYER** — направления + одноразовые действия; `Player.interaction()` находит лестницу или ворота рядом; `startStairs`/`updateStairs` — путь по маршу из точек (до первой ступени → по ступеням → площадка), `updateGate` — проход через ворота (открыть → затемнение → камера едет → выход).
- **CAMERA** — X: следование с упреждением; Y: станция целиком или улица (ступни на 72% высоты кадра), плавный переезд.
- **RENDER** — порядок глубины: фон → бочка → перила (если герой не на марше) → жители → герой → перила (если на марше) → свет → свечение. Пламя и искры бочки рисуются в маленький отдельный слой, из которого вырезаются силуэты героя и жителей, — поэтому огонь никогда не оказывается поверх тела. Сборка кадра, карта света (снаружи светлее — пыльные сумерки), субпиксельный сдвиг по X и Y.

Как добавить жителя: строка `actor('walker', 'worker', x, y, { minX, maxX })` в `placeActors()`. Как добавить ещё одни ворота: запись в `CONFIG.GATES`.

## Ручной тест-план

1. **Бочка:** пройти мимо огня в обе стороны — герой закрывает и бочку, и пламя; искры за ним; свет огня на нём есть.
2. **Марш вверх:** «▲ Подняться» только у нижней площадки (x 636–666); герой идёт по ступеням и выходит на площадку яруса.
3. **Марш вниз:** «▼ Спуститься» на верхней площадке; герой спускается и встаёт у подножия.
4. **Во время марша:** ◀ ▶, повторные ▲/▼, сворачивание Safari — переход не ломается и завершается.
5. **Верхний ярус:** HUD «Лестница» → «Мастерская» → … → «Шлюз»; к проёму западнее x 852 не пройти.
6. **Шлюз:** у ворот «▲ На поверхность»; створки разъезжаются, герой уходит внутрь, камера плавно поднимается, герой выходит из дверей вестибюля.
7. **Улица:** HUD «Поверхность · вестибюль»; мутанты бродят и не нападают; завал слева и забор справа останавливают; пепел в воздухе.
8. **Обратно:** «▼ Вход в метро» → шлюз → марш вниз → платформа.
9. **Жизнь станции:** охрана оглядывается, рабочие ходят, жители спят и сидят; гуляющий житель не заходит на ступени.
10. **Производительность:** с `?debug` FPS и время BUILD.

## Отчёт о тестировании 0.5

Автоматически, headless Chromium (без GPU):
- Сценарии ТЗ 1–10 на 874×402 @3x: проход у бочки покадрово (снимки), подъём и спуск без скачков (Y меняется не больше чем на одну ступень между замерами), кнопки только в своих участках, 5 повторных ▲/▼ + ◀ + `blur` + `visibilitychange` посреди подъёма, камера по Y неподвижна на марше, полный маршрут до улицы и обратно, ошибок JS нет.
- Подъём и спуск на 1280×720 (клавиатура), 874×402 @3x, 844×390 @3x, 568×320 @2x (тач-эмуляция): везде пройдены, ошибок нет.
- FPS у бочки в одинаковых условиях: 0.4 — 60, 0.5 — 60 (headless, не iPhone).

Нужно подтвердить на iPhone (проверяет Андрей): FPS на улице и у бочки, плавность марша на 120 Гц, удобство кнопки ▲/▼ большим пальцем, сворачивание Safari посреди марша. **Значения FPS на iPhone не измерялись.**

## Не проверено на iPhone

- FPS на улице и в шлюзе (больше слоёв и ~25 фигур), нагрев.
- Плавность вертикального переезда камеры на 120 Гц.
- Время появления первой картинки в Safari.
- Сворачивание Safari посреди прохода через ворота.

## Известные ограничения

- Мутанты и жители проходят сквозь героя и друг сквозь друга; реакции нет — так и задумано на этом этапе.
- Спящие нарисованы поворотом обычного кадра — силуэт упрощённый.
- Западное крыло верхнего яруса (жилой блок, столовая) по-прежнему недоступно: видно, но отрезано обломками.
- На марше ступни следуют за ступенями: при ходьбе вверх тело поднимается рывками по 6 px (по ступени) — так задумано, но на iPhone стоит оценить.
- Ореол-свечение у бочки убран, чтобы не ложился на героя; освещение от огня осталось.
- Свет не отбрасывает теней; звука нет.

## Отчёт о тестировании 0.5.2

Автоматически, headless Chromium (не Safari и не iPhone):
- Лестница: снимки «до/после» в одном месте и масштабе (у нижних ступеней и на середине марша). Под маршем просвет со стеной станции; координаты не изменились: подъём заканчивается на x 862, y 98, спуск — на x 652, y 219, как в 0.5.1.
- Регресс 0.5 (сценарии 1–10, в том числе шлюз → улица → обратно) и подъём/спуск на 1280×720, 874×402 @3x, 844×390 @3x, 568×320 @2x — пройдены, ошибок JS нет.
- Service worker (localhost): первый запуск без сети не открывается и ничего не ломает; онлайн-запуск 0.5.1 + чужой кэш `another-app-cache` → обновление до 0.5.2 → остались `another-app-cache` и `poslednyaya-vetka-0.5.2`, старый игровой кэш удалён; офлайн-перезапуск открывает 0.5.2; в кэш игры попадают только её 5 файлов, запрос на чужой сайт мимо кэша.

Не тестировалось на iPhone: FPS, вид нового марша на экране телефона, установка на экран «Домой» и офлайн-запуск с иконки, обновление кэша на устройстве. Это проверяет Андрей.

## Предложение архитектуры электропитания для 0.6 (не реализовано)

1. Каждый источник света и каждый светящийся элемент получает поле `circuit` — имя цепи («зал», «жилой», «техзона», «аварийная») или `null` для неэлектрических (бочка, буржуйка, свеча). Сейчас у многих элементов `light = null` и нет связи с питанием — это и будет заполнено.
2. Новый раздел `POWER`: генератор в энергоблоке → щиты → цепи; у каждой цепи уровень 0…1 (норма, просадка, отключено). Все потребители регистрируются в своей цепи при сборке мира.
3. Яркость считается как сейчас, но умножается на уровень цепи: в `lightIntensity` для градиентов света и в `drawEmissive` для экранов, индикаторов и лампочек. Тогда при блэкауте гаснут и свет, и само свечение; огонь продолжает гореть.
4. Просадка напряжения даёт мерцание ламп цепи, аварийная цепь на аккумуляторах включает красные маяки.
5. Неподвижная часть картинки (корпус монитора, плафон) остаётся в предрисованном слое — переключается только его свечение, поэтому производительность не страдает.

## Вопрос на 0.6: выход на поверхность сбоку платформы (не реализовано)

**Схема А — западный торец.** У баррикады «СТОЙ» (x 40–140) в грунт уходит лестничный коридор вверх-влево, к новому вестибюлю над западным концом станции (x ≈ 0–300). Улица продлевается на запад. Охрана баррикады становится постом выхода. Минус: по легенде это засыпанный тоннель, коридор придётся объяснять как служебный.

**Схема Б — восточный торец, через «ГЕРМОЗАТВОР 2» (рекомендую).** За гермозатвором (x 1878–1970) — наклонный эскалаторный коридор вверх-вправо; мир расширяется на восток примерно до x 2300, туда переезжает нынешний вестибюль с улицей. Гермозатвор, который сейчас просто декорация, получает смысл, охрана уже стоит. Шлюз наверху остаётся карантинным пунктом.

В 0.5 действующий путь через шлюз сохранён без изменений.
