## 4. Порядок выпуска — ТОЛЬКО после команды автора

1. Автор проверяет кандидат на iPhone по превью (чек-лист ниже) и даёт команду «выпускай 1.2.0».
2. Claude открывает PR `release/1.2.0` → `main`. На PR в `main` автоматически запускается проверка `tests`; слияние — только при зелёной проверке.
3. Слияние PR (без force-push). Проверка публикации GitHub Pages.
4. Автор открывает PROD на iPhone: `v1.2.0`, сохранения на месте, чек-лист п. 1–8.
5. **Вручную, сам автор:** тег `v1.2.0` (сессии создание тегов запрещено). Тег `v1.1.0` тоже до сих пор не создан.
6. По отдельному разрешению: `dev` получает релизные правки из `main` (перемотка или слияние) и снова становится `1.2.x-dev`.
7. Обновить статусы в README / PROD_DEV в обеих ветках.
