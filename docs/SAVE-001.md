## 1. Три механизма — три разные записи

| Механизм | Ключ PROD / DEV | Что хранит | Когда пишется | Когда читается |
|---|---|---|---|---|
| A. Session | `pv.session.v2` / `pv.dev.session.v2` | текущее состояние (может быть в опасной зоне) | сворачивание / закрытие PWA, периодически | только «Продолжить» |
| Б+В. Checkpoint | `pv.game.v2` / `pv.dev.game.v2` | `initial` + 1 `auto` + 2 последних ручных (`tea` / `sleep`), счётчик `seq` | авто перед выходом наверх; каждый чай и сон | смерть; «Загрузить сохранение» |
| Резервная копия | `pv.game.v2.bak` / `pv.dev.game.v2.bak` | последняя проверенная копия `pv.game.v2` | после успешной проверки основной записи | если основная испорчена |

Изоляция DEV / PROD — та же `saveKey` (`pv.*` → `pv.dev.*`), что у действующих сохранений.

## 2. Формат (единый, без дублирования)

```
запись  = { v: 2, id: "<source>:<seq>", source: "initial" | "auto" | "tea" | "sleep", seq, at, state, sum }
state   = { scene, floor, x, facing, atmo, hp, maxHp, heal: { tea, sleep }, inv: { wallet, filters, ammo: { <тип>: n } }, flags, world, exitId? }
хранилище = { v: 2, seq, initial, auto | null, manual: [последняя, предыдущая] }
session = { v: 2, at, state, sum }
```

- **Полный снимок:** `state` — самодостаточная копия, не ссылка.
  - Поля будущих систем (HP, лечение, валюта, фильтры, патроны, флаги, мир) уже в формате. Наполнение — по мере появления систем.
  - Состав `inv` (экипировка, магазины, сумка, сюжетные слоты) расширяется по контракту DS-012.
- **Целостность** — контрольная сумма FNV-1a канонического JSON. Любая правка, чужая версия или порча → запись недействительна.
- localStorage **не транзакционен**. Схема записи:
  1. `pv.game.v2`;
  2. повторное чтение и сравнение;
  3. только после совпадения — `.bak`.

  При quota, обрыве или потере записи прежние данные остаются, а вызов возвращает `ok: false`.

## 3. Правила (реализованы в ядре)

- **Чай:** +50 % maxHP, не выше максимума, — только первое применение в лечебном цикле. Сон — до 100 %, тоже один раз за цикл.
  - Каждое повторение сохраняет без лечения, с репликами «Я уже напился чая» / «Я уже выспался».
  - Снимок делается **после** лечения.
- **Лечебный цикл не сбрасывается выходом за дверь.** Новый цикл открывает только событие из списка `HEAL_CYCLE_EVENTS`. Список **пуст**, пока автор не определит событие. До этого лечение доступно один раз за игру (безопасно, без эксплойта).
- **Авто-checkpoint перед выходом на поверхность** — `autoBeforeExit(store, state, exitId)`:
  - на безопасной стороне;
  - идемпотентен для одного фактического выхода (тот же `exitId`);
  - каждый новый выход обновляет запись;
  - в токсичной среде и без `exitId` — отказ.
- **Смерть** — `deathRestore`: последний по `seq` **действительный** auto или manual (испорченный пропускается); нет ни одного — `initial` (комната Глеба). Session не используется.
- **Меню** — `loadMenu` / `loadChoice`: «Продолжить» (session) и «Загрузить сохранение» → авто / последнее ручное / предыдущее ручное.
  - Недоступное помечено с объяснением.
  - Загрузка **заменяет** состояние целиком.
- **Checkpoint запрещён** в токсичной среде и при HP 0 (смерть во время чаепития / сна).
- **Подарок Деда** — `dedGift`: +10 валютных и +2 фильтра вместе с флагом `ded_gift_given`, одна новая копия состояния.
  - Повтор ничего не даёт; `.357` не трогаются.
  - Откат на сохранение до встречи возвращает и флаг, и предметы.
- **Миграция с 1.1.x** — `migrateV1`: прежние `pv.*` **не удаляются и не меняются**.
  - Позиция `pv.player.v1` → session («Продолжить»).
  - Checkpoint из старой позиции **не создаётся** (её безопасность неизвестна) — только `initial`.
